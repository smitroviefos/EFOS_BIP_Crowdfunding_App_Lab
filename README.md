## 💡 Our concept: crowdfunding knowledge, not money

On classic platforms such as Kickstarter, backers support a project with money. In our app, **students back projects with their knowledge and time**.

> **Example:** A computer science student is building a game but knows nothing about marketing. She posts the project and lists the skills it needs – marketing, promotion, a business plan. An economics student backs the project by offering a marketing plan instead of money.

Each team builds a web application with:

- **Must have – CRUD for projects:** post, list, edit and delete projects that need skills
- **Should have – pledges:** a student offers a skill and hours to a project
- **Could have – your own features:** search by skill, user profiles, project status, a “skills covered” progress bar …

## 🎯 Learning outcomes and assessment

By the end of the BIP you will be able to:

1. **Analyse requirements** – formulate and analyse user requirements and develop an application concept, using real crowdfunding campaigns as the case study.
2. **Manage documentation and version control** for a business application.
3. **Build as a team** – design and build an application with data entry, display, editing and deletion (CRUD) from a database, plus features your team chooses.

| Weight | What is assessed |
|:---:|---|
| **40 %** | **Technical functionality** – CRUD works end to end, plus your extra features. Not finished in five days? A prototype or sketch of the whole app is assessed too. |
| **30 %** | **Documentation & version control** – requirements, README, a clean commit history and reviewed pull requests |
| **30 %** | **Collaboration & intercultural reflection** – how your team worked together and what you learned from each other |

## 🍎 Optional: set up at home on a Mac

SQL Server has no native macOS version, so on a Mac you run it in a **Docker container**. On Apple Silicon (M1–M4) Macs the container runs through **Rosetta** emulation – fine for development.

### Step 1 – Install the IDE and .NET

1. Install **[JetBrains Rider](https://www.jetbrains.com/rider/download/)** and choose the free non-commercial licence (or use your [JetBrains student licence](https://www.jetbrains.com/community/education/#students)).
2. Install the latest **[.NET SDK](https://dotnet.microsoft.com/download)** and check it in Terminal:
   ```bash
   dotnet --version
   ```

### Step 2 – Install Docker Desktop (or just use SQLite that comes with JetBrains Rider)

1. Download **[Docker Desktop for Mac](https://docs.docker.com/desktop/setup/install/mac-install/)** – choose **Apple silicon** or **Intel chip** to match your Mac ( → *About This Mac*).
2. **Apple Silicon only:** install Rosetta 2 in Terminal:
   ```bash
   softwareupdate --install-rosetta
   ```
3. **Apple Silicon only:** in Docker Desktop open *Settings → General* and turn on **“Use Rosetta for x86_64/amd64 emulation on Apple Silicon”**, then click *Apply & restart*.

### Step 3 – Run SQL Server 2025 in a container

1. Download the latest image:
   ```bash
   docker pull mcr.microsoft.com/mssql/server:2025-latest
   ```
2. Start the container. Replace `YourStrong!Passw0rd` with your own password – at least 8 characters with upper- and lower-case letters, digits and symbols:
   ```bash
   docker run --platform linux/amd64 \
     -e "ACCEPT_EULA=Y" \
     -e "MSSQL_SA_PASSWORD=YourStrong!Passw0rd" \
     -p 1433:1433 \
     --name sql2025 \
     -v sql2025-data:/var/opt/mssql \
     -d mcr.microsoft.com/mssql/server:2025-latest
   ```
   The `-v` volume keeps your databases when the container is removed or recreated.
3. Check that it is running (status **Up**) and read the log if it is not:
   ```bash
   docker ps
   docker logs sql2025
   ```
4. Next time, simply start or stop it:
   ```bash
   docker start sql2025
   docker stop sql2025
   ```

### Step 4 – Connect to the database

- **In Rider:** *Database* tool window → *+* → *Data Source* → *Microsoft SQL Server*
- **In VS Code:** install the [MSSQL extension](https://marketplace.visualstudio.com/items?itemName=ms-mssql.mssql) and add a connection

| Setting | Value |
|---|---|
| Server / Host | `localhost`, port `1433` |
| Authentication | SQL Login |
| User | `sa` |
| Password | the password from Step 3 |
| Trust server certificate | Yes |

Connection string for the app (keep the password out of Git – see the tip below):

```text
Server=localhost,1433;Database=CrowdfundingDb;User Id=sa;Password=YourStrong!Passw0rd;TrustServerCertificate=True
```

> 🔐 **Tip:** store the connection string with [.NET user secrets](https://learn.microsoft.com/aspnet/core/security/app-secrets) instead of `appsettings.json`, so the password never ends up on GitHub.

### Troubleshooting on a Mac

| Problem | Try this |
|---|---|
| Container stops right after starting | Run `docker logs sql2025`. Check that Rosetta is enabled and that your password is complex enough. |
| Container crashes on macOS 26 (Tahoe) | Early SQL Server 2025 images had problems on macOS 26. Pull the latest image again (`docker pull …:2025-latest`), remove the old container (`docker rm -f sql2025`) and run it again. If it still fails, use `mcr.microsoft.com/mssql/server:2022-latest` instead. |
| Port 1433 already in use | Another container is running – check `docker ps` and stop it, or map another port, e.g. `-p 1434:1433`. |
| Cannot log in | Remember that `MSSQL_SA_PASSWORD` is only applied when the container is first created. Remove the container **and** the volume to start fresh: `docker rm -f sql2025 && docker volume rm sql2025-data`. |

📖 More detail: [Microsoft – Run SQL Server Linux container images with Docker](https://learn.microsoft.com/sql/linux/quickstart-install-connect-docker)

## 🌿 Git cheat sheet

| Command | What it does |
|---|---|
| `git clone https://github.com/[org]/[team-repo].git` | Get the project |
| `git switch main && git pull` | Start from the latest version of main |
| `git switch -c feature/project-edit` | Create a branch for one user story |
| `git status` | See what has changed |
| `git add . && git commit -m "Add project edit page"` | Save your work |
| `git push -u origin feature/project-edit` | Share your branch, then open a pull request |
| `git merge main` | Bring the latest main into your branch |
| `git log --oneline --graph` | See the team’s history |
| `git commit -m "Validate project title. Fixes #14"` | Closes issue #14 when merged into main |

**Team rules:** `main` always works · one branch per user story · small commits written in English · every pull request is reviewed by a teammate, ideally from another university.

## 🤖 Rules for using AI assistants

1. **Understand before you commit** – if you cannot explain it in the code review, do not merge it.
2. **Ask for explanations, not only code** – “Why does this query fail?” teaches more than “fix it”.
3. **Keep secrets out** – never paste passwords, keys or connection strings into a chat.
4. **Say where AI helped** – note it in your team README; transparency is part of good documentation.
5. **Share what works** – keep your best prompts in `PROMPTS.md` in your team repository.
